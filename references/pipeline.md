# 七阶段契约

仅 Web 分支按当前任务需要阅读。先按 [主文件](../SKILL.md) 选择执行方式与设计入口；下列阶段可以合并，产物文件按交接价值保存，不因表中列出就全部创建。用户要求完整阶段时展开执行，无动效阶段可标记不适用。本文件中的文件名映射到项目实际结构；不要求把 React、Vue 等项目改写为静态文件。SwiftUI 项目使用 [原生分支](swiftui.md)。实现与 QA 时按范围应用 [工程质量检查](quality.md)。

## Stage 1 — Blueprint

**职责**：架构与视觉蓝图。别名：Product-Design、UI-UX-Pro-Max。

**输入**：业务需求、受众、核心功能、真实内容、已有品牌与风格参考。

**执行**：

- 查看现有界面和指定参考。需要探索且没有明确视觉目标时按主文件路由到 ideate，默认三张独立方案，选定后才进入实现。已有明确目标或局部修改时沿用，不自动重新选图。
- 按阅读顺序列出页面 Section、核心文案、功能状态和主要行动路径。
- 确立色彩情绪、背景材质、字体搭配、标题与正文反差、圆角、边框和阴影逻辑。描述可实现特征，例如“2px 高对比实线边框”，避免只写“高级、大气”。
- 明确 Hero 视觉锚点及 2–3 个核心交互区域；小页面可以更少。品牌或参考已有明确方向时沿用，不凭空更换。
- 标出加载、空、错误、成功等实际需要的状态，不为展示页虚构复杂业务。

**输出**：简要设计决定；需要保存时使用项目已有记录或 `.agent-context/blueprint.md`，包含页面结构、视觉目标及关键反馈、核心交互和实际文件映射。可沿用 `[Page Architecture]`、`[Visual Direction]`、`[Key Interactions]`，不为简单任务生成空章节。

**边界与检查**：不写 HTML/CSS/JS 实现。确认内容、主要行动和视觉特征足以指导下游，且处于用户授权范围。

## Stage 2 — Tokens

**职责**：设计规范具象化。别名：Design-Tokens & Spec。

**输入**：蓝图、已有主题与设计系统。

**执行**：

- 定义精确颜色：主次背景、主次文字、强调色、辅助色和业务所需状态色。检查文字与背景对比度。
- 建立字号层级，从 `--text-xs` 到 `--text-hero`；需要随视口变化的标题使用 `clamp()`，覆盖约 375px 至 1440px 及以上，同时在 320px 保持可读。用 rem 保留缩放能力，不机械缩小正文。
- 定义间距、圆角、边框、阴影、容器宽度和断点基准。断点优先按现有项目与内容需要决定。
- 复用既有命名与主题机制。没有现有规范时可用 `--bg-*`、`--text-*`、`--accent-*`、`--border-*`、`--shadow-*`、`--space-*`；区分文字颜色与字号变量的用途。
- 局部调整只补确有缺口的值；不重建整套色板或字号。可随组件实现更新现有主题，设计阶段先确定必要约束。

**输出**：`tokens.css` 的 `:root` 变量与必要说明，或现有主题文件中的等效变更。

**边界与检查**：不写业务组件样式。检查颜色、字号、空间与几何参数可供组件复用；流体字号的最小值、缩放段与最大值合理，不破坏已有主题。

## Stage 3 — Motion Spec

**职责**：高光组件与动效逻辑映射。别名：magicuidesign。

**输入**：蓝图、Tokens。

**适用**：滚动编排、鼠标跟随、时间轴、共享元素或其他依赖结构、测量、生命周期的动效。基础 hover、focus 和简单状态过渡可随组件实现；静态任务直接跳过，不创建规格文件。

**执行**：

- 为少量视觉焦点匹配具体交互模式，例如标题交错入场、卡片聚光边框、CTA 反馈。跑马灯、Bento、磁吸和视差只是候选，不是必选。
- 每个效果说明模块、目的、触发条件（Load / Scroll / Hover / Focus）、目标、持续时间与缓动意图。
- 写出必要 DOM 包装层与钩子，例如外层裁切容器、内层变换节点、`data-animate="stagger-up"`、`data-magnetic`。仅约定实现确实需要的层级。
- 为每个效果定义移动端、触屏、reduced motion、JS 失败时的行为；Hover 效果不能承载唯一可用的功能。
- 无需动效的区域明确保留静态。用户要求静态页面时记录该决定，后续不安装或接入动画库。

**输出**：必要的组件映射、结构依赖、触发、清理和降级约定。优先写入已有蓝图；较复杂时独立为 `.agent-context/motion-spec.md`，可用 `[Component Mapping]`、`[DOM Requirements]` 组织。

**边界与检查**：不写 Anime.js / GSAP 时间轴。检查钩子可唯一或按组定位、包装层不会破坏语义和布局，并为所有效果留下可见可用的静态回退。

## Stage 4 — Codex Skeleton

**职责**：Mobile-First 响应式骨架与钩子预埋。

**输入**：蓝图、Tokens、动效规格、现有组件及数据契约。

**执行**：

- 按信息架构编写语义结构，复用项目组件，落实真实内容与必要功能状态。
- 先贯通一条核心操作及其必要错误反馈，在真实页面中检查，再扩展其余区域；轻量任务可与 Stage 5 连续完成，不交付只有外观的空操作。
- 按动效规格预埋包装层和全部钩子；框架项目在组件源代码里声明，不在挂载后临时改写结构。
- 先实现移动端，再向更宽视口增强。新建项目可以 768px、1024px 为起点，用 Grid、`minmax()`、Flex 和可收缩子项形成流式布局。
- 颜色、字号、间距、边框与阴影引用 Tokens；新设计值先在 Tokens 中定义。可使用项目既有主题工具或 utility classes 的等效值。
- 避免不可收缩的固定页面宽度；允许有响应式上限的容器。处理长文本、图片尺寸与横向组件的溢出，而非用全局裁切掩盖问题。
- 键盘可达、表单标签、按钮和链接语义、图片替代文本随骨架完成。

**输出**：可运行的 `index.html`、`styles.css`，或项目等效页面、组件与样式文件。

**边界与检查**：不接入复杂 JS 动画。按 Stage 7 选择代表尺寸，及早检查主要布局、内容与核心操作；运行项目已有且与变更相关的构建、类型或功能检查。后续没有相关改动或新问题时复用已通过的结果。

## Stage 5 — Taste Polish

**职责**：静态视觉与细节打磨。别名：Taste-Skill。

**输入**：骨架、样式、Tokens、动效规格。

**执行**：

- 优化字体层级、行高、字距和对齐。正文阅读宽度可从约 `65ch` 起调，依语言与内容修正。
- 按蓝图有选择地加入材质和层次，例如轻噪点、网格、边框、状态徽章或内阴影，不把这些做成固定套餐。
- 补齐交互元素 `:hover`、`:focus-visible`、`:active` 及必要的 disabled、loading、error 状态；触屏和键盘都能完成核心操作。
- 通过真实浏览器检查桌面与手机的层级、间距、图片裁切、文字换行和状态反馈，再定稿。
- 有选定视觉图时对比同类视口截图，优先修正结构、层级、字号、间距与素材偏差。参考图可能只有一个视口，其他尺寸按内容和现有设计系统适配，不机械拉伸。打磨不另起风格。

**输出**：静态视觉定稿。仅复杂动效需要在蓝图的 `[Freeze]` 或已有规格中记录依赖的组件、钩子和布局边界；基础过渡或无动效任务不写冻结记录。

**边界与检查**：保留响应式策略与所需动效钩子，尺寸调整后复查受影响视口。复杂动效接入不得随意改变其结构依赖；发现结构缺陷时修复、更新对应约定并复测，不为回退阶段另建文档。

## Stage 6 — Anime Motion

**职责**：代码级动效接入与降级。别名：anime。

**输入**：稳定的页面和样式、必要动效约定；有复杂结构依赖时使用已记录的冻结边界。

基础状态过渡已随实现完成时复用其结果；没有动效时直接进入 QA，不新建空模块。用户只请求本阶段时也先核对现有结构与所需约定。

**执行**：

- 绑定预埋钩子，复用现有 Anime.js / GSAP；没有现成库时用 CSS 或 Web Animations API。按安装版本确认 API，不混用不同大版本的调用。
- 选择符合动作含义的弹簧或贝塞尔曲线；入场可参考 `cubic-bezier(0.22, 1, 0.36, 1)`。连续匀速滚动等有意设计可用 linear。
- 高频动画限于 `transform` 和 `opacity`。避免动画化 `width`、`height`、`top`、`left`、`margin`，不以动画覆盖核心布局。
- 根据屏宽和输入能力降级；可从 `(max-width: 768px)`、`(hover: hover)`、`(pointer: fine)` 组合判断，不能仅凭屏宽认定设备。触屏关闭依赖鼠标的跟随与磁吸，缩短位移，避免劫持原生滚动。
- JS 与 CSS 同时处理 `prefers-reduced-motion: reduce`。用户启用时直接呈现动画内容，停止非必要循环；保留必要状态反馈。
- 默认 HTML/CSS 内容可见。仅在动画系统就绪后对已接管的节点施加初态；初始化失败、运行中取消或切换为 reduced motion 时恢复动画影响的样式与可操作性。不要用全局 `opacity: 0` 等待脚本救场。
- 在组件卸载、路由切换或条件变化时清理动画、观察器、监听器和 rAF。滚动优先用合适的观察器，鼠标跟随按帧合并更新；`will-change` 按需短时使用。

**输出**：`motion.js` 或框架动效模块、生命周期接入和必要的增强状态样式。静态任务标记本阶段不适用并进入 QA。

**边界与检查**：保护已约定的 DOM 与布局依赖；必须修复结构时同步更新约定并复测。实测动画触发、触屏降级、减弱动态效果以及页面重新进入；60fps 是性能目标，未经设备和性能轨迹测量不得宣称达成。

## Stage 7 — QA & Perf Audit

**职责**：多视口验证、缺陷修复与证据闭环。别名：Visual-QA、Perf-Audit。

**输入**：完整项目与前述契约。

**执行与验收**：

1. 根据受影响布局选择真实浏览器视口。普通页面默认覆盖窄屏与桌面，例如 375、1440 CSS px，并检查受影响的实际断点两侧；固定平台或局部区域按其支持范围选择。整站、大范围重设计和复杂响应式任务扩展到 **320、375、768、1440、2560 CSS px** 矩阵，并补实际断点两侧；项目明确的支持范围优先。记录实际宽高与缩放，覆盖关键区域、长内容及必要状态，检查横向溢出、遮挡、截断、容器挤压和图片比例。小改动也需覆盖其影响的共享布局和状态。
2. 以键盘、触屏或移动端模拟操作主要流程，检查焦点可见、焦点顺序、按钮与链接行为、表单错误和反馈。需要真实设备的行为，模拟验证不能写成真机通过。
3. 刷新检查首屏闪烁；禁用 JS 后刷新，确认应由初始 HTML 或 SSR 呈现的核心内容没有被动画隐藏。客户端渲染应用另需模拟动效模块失效并保持正常挂载，以区分应用渲染依赖与动画故障。
4. 涉及动效时启用 reduced motion，检查初次加载及运行中切换。确认动画目标可见可用、非必要循环停止，且未意外展开业务上应保持折叠或隐藏的内容。无动画隐藏或初始化依赖的静态修改可将相关故障检查标为不适用，简化不取消已有动效受影响时的验证。
5. 检查控制台、资源错误、重复挂载、监听清理、观察器、持续 rAF 与 `will-change`。有性能疑点时录制实际交互轨迹，检查布局、绘制与长任务；记录测量环境。视觉流畅感不能证明 60fps，静态审查不能证明性能达标。
6. 运行项目已有且相关的构建、类型检查与测试，结合 [工程质量检查](quality.md) 排查 API、状态、列表 identity、本地化和用户反馈。修复根因并复测受影响范围；新增非平凡逻辑用一个有意义的小测试或自检覆盖，不为无关现代化或推测性优化扩张改动。复用同一代码状态上已经通过的检查；后续修改、失败或新疑点才补相应复测。

**输出**：修复后的代码及与风险相称的验收记录。局部和普通单页任务可在回复中说明；复杂任务、需跨会话交接或用户要求时，更新项目已有验收文档或 `.agent-context/audit-report.md`。记录包含：

- 验证对象与运行方式：页面或路由、文件、浏览器和设备或模拟条件。
- 各视口、关键流程、reduced motion、JS/动画失败回退、控制台与相关工程检查的结果。
- 已修复问题、受影响范围及复测证据；必要截图或性能轨迹的路径。
- 明确区分通过、失败、未验证与不适用，并列出仍需处理的事项。

**边界与检查**：仅最小修复 Bug、响应式、性能与无障碍问题，不重构视觉风格。无浏览器或运行环境时完成可做检查，将对应项列为未验证；不要据此声称视觉验收、Production-Ready 或部署成功。
