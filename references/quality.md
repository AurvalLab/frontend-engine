# 工程质量检查

从 SwiftUI Pro 提炼可迁移的工程检查，用于 Web 和 SwiftUI 的实现、局部审查与 QA。按改动涉及的部分读取；具体 API 仍以对应平台和项目版本为准。来源与许可见 [第三方说明](third-party-notices.md)。

## API 与行为

- 先看项目实际依赖、编译器、SDK 和目标系统版本。构建没有警告不等于未用软弃用 API；不确定时查对应版本文档或声明，不能把“有更新写法”等同于旧代码已失效。
- 本任务涉及的 API 选择在兼容范围内处理；无关的现代化、迁移和架构调整单独建议。保留现有部署目标、公共接口与交互语义。
- 改绑定、事件或副作用前，区分用户写入、程序写入、相同值赋值及真实值变化。替换 setter、监听器或 effect 可能改变保存时机和调用次数；先确认行为再改。

## 状态与 identity

- 状态归属应符合生命周期。页面、组件、窗口各自拥有的导航和选择状态不要误放到全局共享；退出与重新进入时的保留或重置应符合产品要求。
- 可插入、删除、重排或过滤的列表使用稳定的业务 ID。不要以位置、每次渲染新建的 UUID 或用户可编辑字段作为 identity；静态列表的合理索引不机械改写。
- 避免渲染时重建需要持续存在的模型、订阅或其他昂贵对象。缓存派生数据时覆盖所有失效路径，不为性能引入陈旧界面。
- 环境、Context 或依赖注入的默认值保持语义稳定。发现频繁更新时结合框架的比较与观察机制定位，不能把 SwiftUI 的具体规则直接套到 React、Vue 等框架。

## 性能与资源

- 定位真实热点后再处理反复执行的排序、过滤、格式化、布局测量和事件工作。大列表按项目现有能力考虑懒加载或虚拟化，不为小数据集增加复杂度。
- 取消或丢弃过期异步结果，清理监听、订阅、观察器、定时器与动画。测试快速切换、重复进入和卸载，不只检查首次加载。
- 优先使用平台已有资源和 HTTP 缓存能力；添加手写缓存前先确认实际缺口。
- 深度优化要记录触发问题、测量证据和复杂度代价；不凭模型字段多、组件长或“可能变慢”就拆架构。一般审查保留建议，实际修复限于已授权范围。

## 无障碍、本地化与反馈

- 交互使用平台语义控件并提供可理解的名称；图标视觉可以简洁，辅助技术仍应知道动作含义。支持相应的键盘或辅助输入，颜色不能是唯一线索。
- 允许文字缩放、长译文和窄窗口，关键功能在自适应布局中仍可到达；检查减弱动态效果。
- 新文案加入项目现有本地化资源，不顺手迁移整个资源体系。使用可本地化插值和 locale 感知的日期、数字与列表格式，保留 API 交换所需的固定格式。
- 用户触发的错误提供可见反馈，关键写入保留错误处理。凭据与敏感数据按平台安全存储约定处理，不放进普通偏好存储或仓库。

## 报告

仅报告有代码或运行证据的问题。每项包含实际文件与行号、触发条件或用户影响、最小修复建议；必要时给简短前后代码。最后按影响排序，并分别标记已修复、建议和未验证，避免用建议数量充当质量证明。
